## Topic 1: The Event Loop

The **event loop** is the mechanism that lets single-threaded JavaScript handle async work without blocking. It coordinates the **call stack**, the **microtask queue** (Promises, `queueMicrotask`), and the **macrotask queue** (`setTimeout`, `setInterval`, I/O).

```js
console.log("1: sync");

setTimeout(() => console.log("2: timeout (macrotask)"), 0);

Promise.resolve().then(() => console.log("3: promise (microtask)"));

console.log("4: sync");

// Output:
// 1: sync
// 4: sync
// 3: promise (microtask)
// 2: timeout (macrotask)
```

**Key Points:**
- Synchronous code runs first, fully draining the call stack.
- After the stack is empty, **all microtasks** run before the next macrotask.
- `Promise.then`/`catch`/`finally` and `await` continuations are microtasks.
- `setTimeout(fn, 0)` does **not** run immediately — it waits for the current stack and all pending microtasks to finish.
- A flood of microtasks can starve macrotasks (e.g. an infinite microtask loop blocks rendering).

## Topic 2: Debouncing & Throttling

Both limit how often a function runs in response to rapid events (typing, scrolling, resizing) — but they behave differently.

```js
// DEBOUNCE: run only after activity has stopped for `delay` ms
function debounce(fn, delay) {
  let timer;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// THROTTLE: run at most once every `limit` ms
function throttle(fn, limit) {
  let waiting = false;
  return function (...args) {
    if (waiting) return;
    fn.apply(this, args);
    waiting = true;
    setTimeout(() => (waiting = false), limit);
  };
}

// Usage
const onSearch = debounce((e) => console.log("search:", e), 300);
const onScroll = throttle(() => console.log("scroll tick"), 200);
```

**Key Points:**
- **Debounce** = "wait until it's quiet." Good for search inputs, autosave, resize-end.
- **Throttle** = "at a steady rate." Good for scroll handlers, mouse-move, infinite scroll.
- Both rely on **closures** to keep `timer`/`waiting` state between calls.
- Use `fn.apply(this, args)` so the original `this` and arguments are preserved.

## Topic 3: Currying & Partial Application

**Currying** transforms a function of many arguments into a chain of functions that each take one argument. **Partial application** fixes some arguments up front and returns a function expecting the rest.

```js
// Normal function
const add = (a, b, c) => a + b + c;

// Curried version
const curriedAdd = (a) => (b) => (c) => a + b + c;
console.log(curriedAdd(1)(2)(3)); // 6

// Partial application
function multiply(a, b) {
  return a * b;
}
const double = multiply.bind(null, 2); // fix a = 2
console.log(double(5)); // 10

// A simple generic curry helper
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) return fn.apply(this, args);
    return (...next) => curried.apply(this, [...args, ...next]);
  };
}
const sum = curry((a, b, c) => a + b + c);
console.log(sum(1)(2)(3));   // 6
console.log(sum(1, 2)(3));   // 6
console.log(sum(1)(2, 3));   // 6
```

**Key Points:**
- Currying always takes **one argument at a time**; partial application can fix **several** at once.
- Both build on **closures** (the inner function remembers earlier arguments).
- `fn.length` tells you how many parameters the original function declared — useful for a generic `curry`.
- Great for creating reusable, configured helpers (e.g. `const log = curry(...)`) and for function composition.

## Topic 4: Optional Chaining (`?.`) & Nullish Coalescing (`??`)

**Optional chaining** safely reads deeply nested properties without throwing if something is `null`/`undefined`. **Nullish coalescing** supplies a fallback only when a value is `null` or `undefined` (not for other falsy values like `0` or `""`).

```js
const user = { profile: { name: "Aryan" } };

// Without optional chaining → throws if profile is missing
// const city = user.address.city; // TypeError

// With optional chaining → returns undefined safely
const city = user?.address?.city;      // undefined
const name = user?.profile?.name;      // "Aryan"

// Optional call & optional index
user.save?.();        // only calls if save exists
arr?.[0];             // safe element access

// Nullish coalescing vs ||
const count = 0;
console.log(count || 10); // 10  (0 is falsy)
console.log(count ?? 10); // 0   (0 is NOT null/undefined)
```

**Key Points:**
- `?.` short-circuits and returns `undefined` the moment it hits `null`/`undefined`.
- `??` only falls back on `null`/`undefined` — safer than `||` when `0`, `""`, or `false` are valid values.
- Combine them: `const port = config?.server?.port ?? 3000;`.

## Topic 5: Promise Combinators (`all`, `race`, `allSettled`, `any`)

These static methods coordinate multiple promises at once instead of awaiting them one by one.

```js
const p1 = Promise.resolve("A");
const p2 = new Promise((res) => setTimeout(() => res("B"), 100));
const p3 = Promise.reject("fail");

// all → waits for ALL; rejects if ANY rejects
Promise.all([p1, p2]).then(console.log);        // ["A", "B"]

// allSettled → waits for all, never rejects
Promise.allSettled([p1, p3]).then(console.log);
// [{status:"fulfilled",value:"A"}, {status:"rejected",reason:"fail"}]

// race → settles with the FIRST to finish (resolve or reject)
Promise.race([p2, p1]).then(console.log);       // "A"

// any → first to FULFILL; rejects only if all reject
Promise.any([p3, p2]).then(console.log);        // "B"
```

**Key Points:**
- `all` — all-or-nothing; great when you need every result and want to fail fast.
- `allSettled` — when you want every outcome regardless of failures.
- `race` — first to settle wins (useful for timeouts).
- `any` — first success wins; ignores rejections unless they all fail.

## Topic 6: Generators & Iterators

A **generator** (`function*`) can pause and resume with `yield`, producing values lazily. It implements the **iterator** protocol, so it works with `for...of` and spread.

```js
function* idMaker() {
  let id = 1;
  while (true) {
    yield id++;
  }
}
const gen = idMaker();
console.log(gen.next().value); // 1
console.log(gen.next().value); // 2

// Finite generator + for...of
function* range(start, end) {
  for (let i = start; i <= end; i++) yield i;
}
console.log([...range(1, 4)]); // [1, 2, 3, 4]

// Custom iterable object
const collection = {
  items: ["x", "y"],
  [Symbol.iterator]() {
    let i = 0;
    return { next: () => i < this.items.length
      ? { value: this.items[i++], done: false }
      : { value: undefined, done: true } };
  },
};
console.log([...collection]); // ["x", "y"]
```

**Key Points:**
- `yield` pauses execution and hands a value back; `next()` resumes it.
- Generators are **lazy** — values are produced only when requested (good for infinite/large sequences).
- Any object with a `[Symbol.iterator]()` method is iterable and works with `for...of`, spread, and destructuring.

## Topic 7: Map & Set

**`Map`** stores key→value pairs with keys of **any type** (not just strings). **`Set`** stores **unique** values. Both are iterable and remember insertion order.

```js
// Map
const m = new Map();
m.set("name", "Aryan");
m.set(42, "number key");
const objKey = {};
m.set(objKey, "object key");

console.log(m.get(42));      // "number key"
console.log(m.has("name"));  // true
console.log(m.size);         // 3
for (const [k, v] of m) console.log(k, v);

// Set
const s = new Set([1, 2, 2, 3, 3, 3]);
console.log([...s]);   // [1, 2, 3]  (duplicates removed)
s.add(4);
console.log(s.has(2)); // true

// Common trick: dedupe an array
const unique = [...new Set([1, 1, 2, 3])]; // [1, 2, 3]
```

**Key Points:**
- `Map` keys can be objects, functions, numbers — `Object` keys are always strings/symbols.
- `Map`/`Set` keep **insertion order** and expose `.size` (not `.length`).
- `Set` is the cleanest way to dedupe arrays.
- `WeakMap`/`WeakSet` hold keys weakly (garbage-collectable) — useful for private data without memory leaks.

## Topic 8: Type Coercion & Equality (`==` vs `===`)

JavaScript converts types automatically in many operations. Understanding coercion and the two equality operators prevents subtle bugs.

```js
// Loose equality (==) coerces types
console.log(0 == "");        // true
console.log(0 == "0");       // true
console.log(null == undefined); // true
console.log([] == false);    // true

// Strict equality (===) checks type AND value, no coercion
console.log(0 === "");       // false
console.log(0 === "0");      // false

// Truthy / falsy
// Falsy values: false, 0, -0, 0n, "", null, undefined, NaN
if (!"") console.log("empty string is falsy");
console.log(Boolean("hello")); // true

// String + number coercion
console.log("5" + 1); // "51"  (number → string)
console.log("5" - 1); // 4     (string → number)
```

**Key Points:**
- Prefer `===` / `!==` by default to avoid surprising coercion.
- Memorize the **8 falsy values**; everything else is truthy (including `"0"`, `[]`, `{}`).
- `+` with a string concatenates; `-`, `*`, `/` force numeric coercion.
- `null == undefined` is `true`, but `null === undefined` is `false`.

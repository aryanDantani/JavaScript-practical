## Topic 1: `async` / `await`

**`async/await`** is syntactic sugar over Promises, making asynchronous code read like synchronous code.

```js
// Promise-based
function getUser() {
  return fetch("https://api.example.com/user")
    .then((res) => res.json())
    .then((data) => data);
}

// async/await equivalent
async function getUser() {
  const res = await fetch("https://api.example.com/user");
  const data = await res.json();
  return data;
}

// Error handling with try/catch
async function loadUser() {
  try {
    const res = await fetch("https://api.example.com/user");
    const data = await res.json();
    console.log(data.name);
  } catch (err) {
    console.error("Failed:", err);
  }
}
```

**Key Points:**
- `async` before a function makes it always return a Promise.
- `await` pauses execution inside the function until the Promise resolves.
- Use `try/catch` for error handling instead of `.catch()`.
- `await Promise.all([f1(), f2()])` runs multiple async calls in parallel.

## Topic 2: Destructuring Assignment

**Destructuring** lets you unpack values from arrays or properties from objects into distinct variables in one line.

```js
// Object destructuring
const user = { name: "Aryan", age: 22, city: "Ahmedabad" };
const { name, age } = user;
console.log(name); // "Aryan"

// With renaming
const { name: fullName } = user;
console.log(fullName); // "Aryan"

// Default values
const { country = "India" } = user;
console.log(country); // "India"

// Array destructuring
const colors = ["red", "green", "blue"];
const [primary, , tertiary] = colors;
console.log(primary);  // "red"
console.log(tertiary); // "blue"

// Function parameter destructuring
function greet({ name, city }) {
  console.log(`Hello ${name} from ${city}!`);
}
greet(user); // "Hello Aryan from Ahmedabad!"
```

**Key Points:**
- Object destructuring matches by **key name**; array by **position**.
- You can set default values if a property is `undefined`.
- Very common in React for `props` and `useState`.
- Works with nested objects too: `const { address: { zip } } = user`.

## Topic 3: The Spread & Rest Operator (`...`)

Both use `...` syntax but do opposite things — **spread expands**, **rest collects**.

```js
// --- SPREAD ---
// Copy an array
const nums = [1, 2, 3];
const copy = [...nums, 4, 5];
console.log(copy); // [1, 2, 3, 4, 5]

// Merge objects
const defaults = { theme: "dark", lang: "en" };
const userPrefs = { lang: "hi", fontSize: 16 };
const settings = { ...defaults, ...userPrefs };
console.log(settings); // { theme: "dark", lang: "hi", fontSize: 16 }

// Pass array as function arguments
const values = [10, 20, 30];
console.log(Math.max(...values)); // 30

// --- REST ---
// Collect remaining arguments
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1, 2, 3, 4)); // 10

// Skip first element, collect rest
const [first, ...remaining] = [10, 20, 30, 40];
console.log(first);     // 10
console.log(remaining); // [20, 30, 40]
```

**Key Points:**
- **Spread** (`...array`) expands elements — used in calls, literals, copies.
- **Rest** (`...params`) collects multiple values into one array — used in function params and destructuring.
- Spread creates **shallow copies** — nested objects are still referenced.
- Both are essential for writing clean, functional JavaScript.

## Topic 1: `async` / `await`

**`async/await`** is syntactic sugar over Promises, making asynchronous code read like synchronous code.

```js
// Promise-based
function getUser() {
  return fetch("https://api.example.com/user")
    .then((res) => res.json())
    .then((data) => data);
}

// async/await equivalent
async function getUser() {
  const res = await fetch("https://api.example.com/user");
  const data = await res.json();
  return data;
}

// Error handling with try/catch
async function loadUser() {
  try {
    const res = await fetch("https://api.example.com/user");
    const data = await res.json();
    console.log(data.name);
  } catch (err) {
    console.error("Failed:", err);
  }
}
```

**Key Points:**
- `async` before a function makes it always return a Promise.
- `await` pauses execution inside the function until the Promise resolves.
- Use `try/catch` for error handling instead of `.catch()`.
- `await Promise.all([f1(), f2()])` runs multiple async calls in parallel.

## Topic 2: Destructuring Assignment

**Destructuring** lets you unpack values from arrays or properties from objects into distinct variables in one line.

```js
// Object destructuring
const user = { name: "Aryan", age: 22, city: "Ahmedabad" };
const { name, age } = user;
console.log(name); // "Aryan"

// With renaming
const { name: fullName } = user;
console.log(fullName); // "Aryan"

// Default values
const { country = "India" } = user;
console.log(country); // "India"

// Array destructuring
const colors = ["red", "green", "blue"];
const [primary, , tertiary] = colors;
console.log(primary);  // "red"
console.log(tertiary); // "blue"

// Function parameter destructuring
function greet({ name, city }) {
  console.log(`Hello ${name} from ${city}!`);
}
greet(user); // "Hello Aryan from Ahmedabad!"
```

**Key Points:**
- Object destructuring matches by **key name**; array by **position**.
- You can set default values if a property is `undefined`.
- Very common in React for `props` and `useState`.
- Works with nested objects too: `const { address: { zip } } = user`.

## Topic 3: The Spread & Rest Operator (`...`)

Both use `...` syntax but do opposite things — **spread expands**, **rest collects**.

```js
// --- SPREAD ---
// Copy an array
const nums = [1, 2, 3];
const copy = [...nums, 4, 5];
console.log(copy); // [1, 2, 3, 4, 5]

// Merge objects
const defaults = { theme: "dark", lang: "en" };
const userPrefs = { lang: "hi", fontSize: 16 };
const settings = { ...defaults, ...userPrefs };
console.log(settings); // { theme: "dark", lang: "hi", fontSize: 16 }

// Pass array as function arguments
const values = [10, 20, 30];
console.log(Math.max(...values)); // 30

// --- REST ---
// Collect remaining arguments
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1, 2, 3, 4)); // 10

// Skip first element, collect rest
const [first, ...remaining] = [10, 20, 30, 40];
console.log(first);     // 10
console.log(remaining); // [20, 30, 40]
```

**Key Points:**
- **Spread** (`...array`) expands elements — used in calls, literals, copies.
- **Rest** (`...params`) collects multiple values into one array — used in function params and destructuring.
- Spread creates **shallow copies** — nested objects are still referenced.
- Both are essential for writing clean, functional JavaScript.

## Topic 4: `map()`, `filter()`, and `reduce()`

These are the three most powerful **array methods** in JavaScript for transforming data without mutating the original array.

```js
const numbers = [1, 2, 3, 4, 5, 6];

// map() — transform every element, returns new array of same length
const doubled = numbers.map((n) => n * 2);
console.log(doubled); // [2, 4, 6, 8, 10, 12]

// filter() — keep only elements that pass the test
const evens = numbers.filter((n) => n % 2 === 0);
console.log(evens); // [2, 4, 6]

// reduce() — boil array down to a single value
const total = numbers.reduce((acc, n) => acc + n, 0);
console.log(total); // 21

// Chaining all three
const result = numbers
  .filter((n) => n % 2 === 0)   // [2, 4, 6]
  .map((n) => n * 10)            // [20, 40, 60]
  .reduce((acc, n) => acc + n, 0); // 120
console.log(result); // 120

// Real-world: extract names of active users
const users = [
  { name: "Aryan", active: true },
  { name: "Raj", active: false },
  { name: "Priya", active: true },
];
const activeNames = users
  .filter((u) => u.active)
  .map((u) => u.name);
console.log(activeNames); // ["Aryan", "Priya"]
```

**Key Points:**
- `map()` — transforms; always returns array of **same length**.
- `filter()` — selects; returns array of **same or shorter length**.
- `reduce()` — aggregates; returns a **single value** (number, object, string).
- None of them mutate the original array.
- They can be **chained** together for powerful data pipelines.

## Topic 5: Hoisting

**Hoisting** is JavaScript's behavior of moving variable and function declarations to the top of their scope before code executes.

```js
// --- Function hoisting (fully hoisted) ---
sayHello(); // Works! ✅
function sayHello() {
  console.log("Hello!");
}

// --- var hoisting (declaration hoisted, not value) ---
console.log(x); // undefined (not an error)
var x = 10;
console.log(x); // 10

// --- let / const hoisting (hoisted but NOT initialized) ---
console.log(y); // ❌ ReferenceError: Cannot access 'y' before initialization
let y = 20;

// --- Temporal Dead Zone (TDZ) ---
// The period between hoisting and initialization of let/const is the TDZ
{
  // TDZ starts here for 'name'
  console.log(name); // ❌ ReferenceError
  let name = "Aryan"; // TDZ ends here
  console.log(name); // "Aryan"
}
```

**Key Points:**
- `function` declarations are **fully hoisted** — callable before their definition.
- `var` is hoisted but initialized as `undefined` until the assignment line.
- `let` and `const` are hoisted but stay in the **Temporal Dead Zone (TDZ)** — accessing them before declaration throws a `ReferenceError`.
- Always declare variables at the top of their scope to avoid confusion.
- Prefer `let`/`const` over `var` to avoid unexpected hoisting bugs.

## Topic 6: `this` Keyword

**`this`** refers to the object that is currently executing the function — its value depends on **how** the function is called.

```js
// 1. Global context
console.log(this); // window (browser) / global (Node.js)

// 2. Object method — this = the object
const user = {
  name: "Aryan",
  greet() {
    console.log("Hi, I'm " + this.name);
  },
};
user.greet(); // "Hi, I'm Aryan"

// 3. Regular function — this = undefined (strict mode) or global
function show() {
  console.log(this); // undefined in strict mode
}

// 4. Arrow function — this is inherited from surrounding scope (lexical)
const obj = {
  name: "Aryan",
  greet: () => {
    console.log(this.name); // undefined — arrow doesn't have its own 'this'
  },
  greetCorrect() {
    const arrow = () => console.log(this.name); // 'this' = obj
    arrow();
  },
};
obj.greetCorrect(); // "Aryan"

// 5. Explicit binding with call, apply, bind
function introduce(city, country) {
  console.log(`${this.name} from ${city}, ${country}`);
}
const person = { name: "Aryan" };
introduce.call(person, "Ahmedabad", "India");   // direct call
introduce.apply(person, ["Ahmedabad", "India"]); // array args
const bound = introduce.bind(person, "Ahmedabad");
bound("India"); // reusable bound function
```

**Key Points:**
- `this` in a **method** = the object before the dot.
- `this` in an **arrow function** = inherited from the enclosing scope (lexical).
- `call()` and `apply()` invoke immediately with custom `this`; `bind()` returns a new function.
- Arrow functions are ideal for callbacks to preserve `this` from outer scope.

## Topic 7: Prototypes & Prototype Chain

Every JavaScript object has a hidden `[[Prototype]]` link. When you access a property, JS looks up this chain until it finds it or reaches `null`.

```js
// Every function has a .prototype object
function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function () {
  console.log(`${this.name} makes a sound.`);
};

const dog = new Animal("Dog");
dog.speak(); // "Dog makes a sound."
console.log(dog.hasOwnProperty("name"));  // true  (own property)
console.log(dog.hasOwnProperty("speak")); // false (inherited from prototype)

// Prototype chain lookup
console.log(dog.__proto__ === Animal.prototype); // true
console.log(Animal.prototype.__proto__ === Object.prototype); // true
console.log(Object.prototype.__proto__); // null (end of chain)

// Modern class syntax (same prototype mechanism under the hood)
class Vehicle {
  constructor(type) {
    this.type = type;
  }
  describe() {
    return `This is a ${this.type}`;
  }
}

class Car extends Vehicle {
  constructor(brand) {
    super("car");
    this.brand = brand;
  }
  info() {
    return `${this.brand} — ${this.describe()}`;
  }
}

const myCar = new Car("Toyota");
console.log(myCar.info()); // "Toyota — This is a car"
```

**Key Points:**
- Every object has `__proto__` pointing to its prototype.
- Property lookup walks up the chain: own → prototype → Object.prototype → null.
- `hasOwnProperty()` checks only the object itself, not the chain.
- `class` and `extends` are clean syntax over the same prototype mechanism.
- Avoid mutating `Object.prototype` — it affects every object.

## Topic 8: Modules (ES6 `import` / `export`)

ES6 Modules let you split code into reusable files with explicit imports and exports.

```js
// --- math.js ---
export const PI = 3.14159;

export function add(a, b) {
  return a + b;
}

export function multiply(a, b) {
  return a * b;
}

// Default export (one per file)
export default function square(n) {
  return n * n;
}

// --- main.js ---
// Named imports
import { PI, add, multiply } from "./math.js";
console.log(PI);          // 3.14159
console.log(add(2, 3));   // 5

// Default import (any name you choose)
import square from "./math.js";
console.log(square(4)); // 16

// Import everything as namespace
import * as Math from "./math.js";
console.log(Math.multiply(3, 4)); // 12

// Rename on import
import { add as sum } from "./math.js";
console.log(sum(10, 5)); // 15
```

**Key Points:**
- **Named exports** — multiple per file, imported with exact name in `{}`.
- **Default export** — one per file, imported without `{}` with any name.
- Modules are **always in strict mode** by default.
- Use `type="module"` in `<script>` tags for browsers: `<script type="module" src="main.js">`.
- ES Modules are **static** — imports are resolved at parse time, not runtime.
